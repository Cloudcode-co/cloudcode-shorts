# unkernel-linux-webassembly

An ops-console explainer: ten long dashboard takes (one per voice beat) on a deep-pine console, with mint telemetry lifted from pithings' avatar, amber for emulated layers and red for the JSPI gate. Headlines are Bricolage Grotesque, all counters/logs/commands are JetBrains Mono, and the benchmark numbers are the project's own (0.300 s boot, 60 µs fork, 10 MB / 48 MiB, 170 ns `getppid`, 0.8 s / 3.4 s `apk`). The compile shot is a `<GsapScene>` (`scenes/Compile.tsx`) and the Wisp network shot is a HyperFrames clip (`hf/wisp/`) played with `<HfClip>`; `npx unkernel` is typed through the kit `Terminal`.

QA fixes: the install shot no longer uses the stock keyboard footage; the terminal panel now fills the safe area on its own, with `npx unkernel` typed through the kit `Terminal`, a boot meter and the `alpine` / `mạng` readouts lighting up as it executes. The boot ruler marker now sits at 0.300 of a 1.000 s axis instead of at the animation's end; the late reveals that left empty lower halves were pulled earlier (boot rows, v86 comparison strip, kernel user/metric panels, fork bars, budget boot panel); the compile source caption is no longer clipped and the health metadata no longer wraps; the out-of-frame `native` bar, the repo-header collision, the `WebSocket`/globe label overlap, the over-wide JSPI caveat line, the two-column hook rows and the crowded `getppid` rail were all recomposed. The Wisp pulse rings that read as nested boxes were removed.

Note: this sandbox has no system ffmpeg, so `npm run hyperframes` was run with the bundled `@remotion/compositor-linux-x64-gnu` ffmpeg on `PATH` (a wrapper drops the unsupported `setparams` tag). The clip renders at 60 fps from `data-fps="60"`; the MP4 is regenerated from `hf/wisp/index.html` in the normal pipeline.
